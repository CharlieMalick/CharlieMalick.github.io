NYC 311 Service Request Modeling

Developed a scalable data pipeline and predictive model to categorize daily complaint volumes for NYC city agencies. By leveraging AWS cloud infrastructure and historical 311 data, this project provides a framework for city departments to anticipate high-demand periods and allocate resources more effectively.

Python AWS S3 AWS Athena Scikit-learn Logistic Regression SQL
More details

Problem

NYC's 311 system processes millions of requests annually, ranging from noise complaints to infrastructure repairs. City agencies often struggle to anticipate "surge" days where complaint volumes exceed typical thresholds. The goal was to create a modeling plan that could categorize upcoming service request volumes into 'low', 'medium', or 'high' priority levels based on historical temporal patterns.

Approach

Stored and managed massive datasets within AWS S3 buckets and utilized AWS Athena for serverless SQL queries to perform feature engineering on millions of rows. I developed a modeling plan using Logistic Regression to classify daily complaint volumes. The pipeline involved extracting data from the SCHOLAR repository, cleaning temporal features, and preparing the data for a cloud-native machine learning workflow.

Results & Impact

The modeling plan established a clear path for using cloud-based data warehousing to drive urban operational decisions. By successfully categorizing complaint volumes using logistic regression, the project demonstrated how city agencies can transition from reactive to proactive staffing. This work serves as a cornerstone of my senior year work at Michigan State University.

Red Wine Supernova: Quality Prediction

Explored the chemical profiles of red and white wines to determine which laboratory measurements most significantly influence quality ratings. Developed a predictive model to forecast quality scores while addressing challenges like imbalanced classes and feature multicollinearity.

Python Pandas Scikit-learn Seaborn Matplotlib
More details

Problem

Wine quality is often perceived as subjective, but it is driven by objective chemical properties. The goal of this project was to determine if laboratory measurements—such as acidity, residual sugar, and alcohol content—could accurately predict the quality scores assigned by experts. A key challenge was the imbalanced nature of the dataset, which featured a high concentration of "average" quality wines.

Approach

Merged and processed the UCI Red and White Wine datasets, implementing feature engineering by creating dummy variables for wine color. Performed Exploratory Data Analysis (EDA) to identify highly correlated features, such as density and alcohol, that could cause multicollinearity. Utilized Scikit-learn to build and evaluate predictive models, focusing on handling class imbalances to improve the detection of "exceptional" wine ratings.

Results & Impact

Identified alcohol content and volatile acidity as primary indicators of quality. The project established a reproducible pipeline for chemical data analysis and highlighted the importance of data preprocessing in environmental and food science modeling. This analysis provides a framework for using objective data to standardize quality assessments in the viticulture industry.

Containerized Sales & Weather Analysis

Developed a robust data analysis pipeline to correlate regional sales revenue with Detroit weather patterns. The project emphasizes reproducibility by utilizing Docker containers and multiple environment management strategies (Conda/Venv) to ensure consistent results across different operating systems.

Docker Python Pandas Conda Bash Matplotlib
More details

Problem

Data analysis scripts often fail when moved between machines due to version mismatches or missing dependencies. The goal of this project was to build a multi-source analysis tool—integrating employee, sales, and weather data—and wrap it in a containerized environment. This ensures that the "lion's share" of the cleaning and analysis logic remains portable and bug-free for any end-user.

Approach

Implemented a modular Python architecture consisting of dedicated scripts for data handling and cleaning. I engineered a pipeline that processes customer lookups, January sales records, and weather data. To solve the "it works on my machine" problem, I authored a Dockerfile to containerize the application, allowing the entire analysis to run in an isolated environment with mounted volumes for persistent output storage.

Results & Impact

Successfully automated the generation of regional revenue summaries and data visualizations. By providing both Conda environment configurations and Docker support, I reduced setup friction for collaborators. This project demonstrates my ability to handle real-world engineering challenges like relative pathing, Python version mismatches, and automated container builds—core competencies for a future Data Engineer.
